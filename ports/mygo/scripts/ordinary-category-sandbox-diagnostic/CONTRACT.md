# Bounded sandbox platform diagnostics

This is a separate development diagnostic, not an oracle capture or a product runtime. It investigates an observed SIGABRT from sandboxed xcodebuild without changing the sandbox. All results retain captureComplete, swiftExecuted, semanticParityVerified and runtimeAdmission=false, including three successful probes. No Swift, compiler, xcrun, shell, product data, crash report or system log is invoked/read.

## Trust and inputs

The workflow bootstraps the exact reviewed driver bytes before execution. The driver checks its external reviewed SHA, the local four-file closure (driver, tests, this contract, workflow), and fixed old runner/source/tool/input hashes. CLOSURE.json is a checked local inventory, not an independent signature. Review the workflow/closure together; the workflow is independently frozen for publication. The old runner is read using bounded nofollow file descriptors and verified before compile/exec into a non-main module. All reused functions come from that one verified module, not a subsequent path import. No bytecode is written.

Only verify/probe/export actions and typed run ID/attempt/head plus external absolute work/evidence roots are accepted. The developer directory is fixed at /Applications/Xcode_26.2.app/Contents/Developer. Roots cannot overlap each other or the checkout. New roots reject existing paths including dangling links; files reject symlink ancestors/leaves, hardlinks and over-budget contents. Source closure staging and before/after checks use the original runner unchanged.

## Execution

A: /usr/bin/true; B: /usr/bin/xcodebuild -version; C: fixed developer/usr/bin/xcodebuild -version. Every argv begins /usr/bin/sandbox-exec -f <work>/compile.sb. The compile profile is generated by the exact frozen original sandbox function, not adapted or broadened. Actual profile bytes/hash and file identity are checked before/after launches. Original bounded_process handles new session, DEVNULL stdin, work cwd, pipe bounds and group cleanup; its capture function is never called.

Executable inspection uses nofollow path walks, regular/executable and non-group/world-writable mode checks, and records dev/ino/mode/uid/nlink/size/mtime/ctime. Large or multi-hardlinked legitimate system files are allowed; no source input size limit is imposed on Mach-O files. Metadata is rechecked immediately before/after. This is not an atomic pathname exec binding or protection against a malicious administrator. C being absent or unsafe is typed not-run, never a fallback. A/B/sandbox-exec unavailability stops the plan.

Each helper receives 20 seconds; a single 120-second monotonic command-phase deadline starts after staging, and launch requires at least31 seconds remaining. The original helper allows up to5 seconds reap plus5 seconds group disappearance. This is a cooperative phase budget, not a hard realtime bound for blocked OS calls. The5-minute workflow timeout is a last stop, not proof of cleanup.

The child environment has exactly PATH=/usr/bin:/bin, private HOME/TMPDIR, LANG/LC_ALL=en_US.UTF-8, TZ=UTC, fixed DEVELOPER_DIR and private CLANG_MODULE_CACHE_PATH. No inherited tokens, DYLD flags, proxies or user environment. The Python parent is not itself sandboxed.

Only an ordinary nonzero return with exactly one ledger/matching disk receipt, complete transport/cleanup, valid UTF8 and stable identities may continue. Timeout, overflow, unknown exception, changed identity/profile, receipt uncertainty or cleanup uncertainty stop later commands. Missing receipts become unknown slots, not fake attempts. No retries. Preserved receipts are not modified to claim success. Version success requires the exact first stdout line Xcode26.2 (with a space: `Xcode 26.2`). A failing or unavailable probe makes CLI nonzero even when the diagnostic plan is completely explained.

## Evidence

Schema ordinary-category-sandbox-diagnostic-v1; purpose platform-preflight-diagnostic-only. Summary has exactly three typed slots (attempted/not-run/unknown), fixed false product flags, bounded selected image metadata, source identities, actual profile hash and command-phase duration. Unknown fields, duplicate JSON keys, bool-as-integer and nonfinite times fail closed. diagnosticComplete means the plan was interpreted, not that platform tools worked. Status distinguishes completed, probe-failure, incomplete and setup-failure.

Export validates exact dependencies and workflow before reading fixed paths, then revalidates the summary, profile and original command/stream receipts. The archive contains only summary.json, compile.sb, and three files for each actual attempt: command receipt and one raw-or-prefix stream each for stdout/stderr. Maximum11 members, 32KiB summary, 8KiB profile/receipt, 64KiB each stream, 512KiB uncompressed and ZIP. Counts may exceed retained prefix size; they never imply full originals. No recursive input or extra files are archived. Work/home/tmp/cache/build/input/provenance are never uploaded.

The two output paths are sandbox-diagnostic-evidence.zip and export-summary.json. Missing/untrusted work produces only a fixed structured failure summary, no plausible empty evidence ZIP. Obvious credential/private-path patterns and invalid UTF8 fail closed to a summary; this limited text check is not a universal guarantee against every unforeseen OS message. No arbitrary exception repr or filesystem listing is included in that failure summary. Existing oracle schema/exporter/upload whitelist remains unchanged.

## Verification boundary

Local tests use temporary synthetic protocol files and mocks, never macOS execution. They cannot prove sandbox loading, Xcode availability, SIGABRT cause or Swift parity. Run verify/test with Python -B and PYTHONDONTWRITEBYTECODE=1. A future exact hosted run requires its own review; even successful probes do not change the original oracle or authorize wider access. Fixed upstream Swift, manifest and all old workflows remain untouched.
