## 症状、根因与修正

1. 旧 A 保存中出现 AB 输入，重复关闭／观察导致已到期新候选被过早提交，正常 Gate 拒绝被误当失败，清除关闭意图。`pump` 现在保留候选等待已有 flight 完成，再读取新 native 输入并继续原意图。反例在修复前出现三次 ErrNotReady，修复后按序保存 A、AB，不能先关闭。
2. 日界结算未检查共享停止状态，也未记录失败的日期尝试。错误重绘会立即再写，甚至已不完整的会话仍推进日期。现在执行前检查停止标记、锁存永久失败，并阻止错误自己的 redraw 重试；普通明确命令仍由领域边界核验。
3. 旧导航完成清除了新导航目标，或关闭后遗留目标闭包。现在目标带单调身份，旧完成不能抹去新意图，取消／覆盖／关闭释放自身闭包。存储成功也不能掩盖其后原生读取失败。
4. 把写入搬到后台仍不够：UI 的 Snapshot／Today 读锁会被跨磁盘提交的 Service 写锁阻塞。现在 UI 只读取已确认、按 FIFO 发布的深复制快照；新窗口也从该视图初始化。真实 Service 持锁暂停时仍可重绘，释放写入但尚未交付 publication 时仍只显示旧事实。
5. 原同步排期改为异步后，旧完成可在取消→换日→重开弹窗后关闭新弹窗并覆盖选择；快速重复同动作会用第二次非法转换错误遮盖第一次成功。现在完成只可影响匹配的弹窗身份、页面、日期与选择；共享 hub 按不可变动作键去重在途的相同排期或完成动作，不吞掉独立合法命令。领域写入仍正常完成，不把取消界面冒称撤回已接受事务。
6. 为排空后台任务而把事件循环错误改成仅打印日志，会错误返回成功退出码。现先完成清理，再对启动错误返回非零；`TestRuntimeExitStatusCleansBeforeReturningFailure` 覆盖 helper 顺序与状态，不将该测试冒称真实窗口启动验收。

## 复现与排除

使用真实 MyGo Tester、实际 Handle 与新建合成 Service，队列／时钟确定性推进。任务池反例使用真正点击、取消、下一日和重新打开，不直接篡改最终 UI 状态。磁盘四阶段 fault 和持锁 barrier 只注入测试隔离资料。

排除“多等一帧即可”“成功写盘等于最新 native 已确认”“后台写入等于 UI 不会阻塞”“领域不重复就没有界面问题”等假设。没有通过 timeout 放行关闭、忽略保存错误或取消已接受事务来绕过根因。
