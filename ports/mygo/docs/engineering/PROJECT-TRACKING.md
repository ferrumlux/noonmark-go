# 研发追踪与证据闭环

## 入口与事实来源

- [研发总览 #1](https://github.com/ferrumlux/noonmark-go/issues/1)：分栏导航、阶段与依赖。
- [全部 Issues](https://github.com/ferrumlux/noonmark-go/issues)：每项任务的事实、实现、审查、验证与关闭记录。
- [当前能力](../../README.md)、[迁移审计](../migration-audit/NOONMARK-MYGO-MIGRATION.md)、[发行门禁](../release/RELEASING.md)：能力声明与退出条件。

当前使用 **GitHub Issues 总览表 + 状态标签**。没有建立 GitHub Projects 原生拖拽看板，也没有自动同步。总览表由维护者在状态变化时更新；实时查询以 Issue 标签为准。将来新增其他看板时，应保留 GitHub Issue 编号和证据链接，不建立冲突的第二套事实。

## 状态与优先级

每项 Issue 只保留一个 `status: ` 标签。

| 状态 | 进入条件 | 离开条件 |
| --- | --- | --- |
| 待办 | 范围与验收已登记，尚未实际开工 | 执行人开始工作后转进行中 |
| 进行中 | 实际开发、审查或验证正在进行 | 产物就绪转待验证；外部依赖卡住转受阻 |
| 待验证 | 范围内实现已准备或同步，适用验收未齐 | 证据齐备才完成；失败回进行中或受阻 |
| 受阻 | 缺环境、依赖、权限或前置验收 | 写清解除条件，解除后恢复实际状态 |
| 已完成 | 本项验收逐条满足，有关闭摘要与证据 | 发现回归或证据失效时重新打开 |

`priority: P0` 为当前阻断或数据正确性风险，P1 为本阶段关键工作，P2 为后续阶段，P3 为改善项。`area: ` 表示模块。新增标签不改变授权范围；负责人和节点日期仅在明确后填写。

持续总览可以保持打开并标进行中，但不计作待交付产品工作。取消、重复或不再计划的任务应说明原因并按 `not_planned`/`duplicate` 关闭，不贴已完成标签。受阻不是已完成，不能为清空待办而关闭。

## 开始、更新与关闭

1. 建项前搜索现有 Issue，记录来源 commit、范围、验收清单、依赖与下一步。大 epic 分拆可独立验证的子任务。
2. 开工后更新状态。实现使用独立候选；共享 main 的整合串行进行，不能以覆盖整棵目录吸收并行变更。
3. 每次有实质进展，在对应 Issue 评论记录日期、commit、工作结果、实际命令/exit、证据链接、未覆盖项与下一步。无进展不堆砌空日志。
4. 代码、文档和 PR 引用 Issue。已有 `Task-Id` 保留，同时补 `Refs #N`；原有任务文档继续使用，不复制一份互相漂移的测试报告。
5. 验收前区分被测产品 commit、后续纯文档 commit和当前 main。CI 必须核对 `head_sha`。若文档随批准摘要变化会使发行门禁失效，按原发行流程重做，不借「文档而已」绕过。
6. 关闭前填写下面的摘要，核对每项验收，设已完成并关闭 Issue，最后更新总览表。未覆盖的大范围能力保持关联 Issue 打开。
7. 缺陷重现或来源变化使证据失效时重新打开，记录原因、影响和需要重跑的验证，不删除失败历史。

### 进度评论格式

```text
日期（UTC）：
范围 / Issue：
被测 commit：

实际验证（命令、exit、CI）：
证据：
未覆盖 / 阻塞：

```

### 关闭摘要

```text
验收逐项结果：
最终实现 commit / PR：
被测版本与实际证据：
回归与独审：
兼容 / 回滚边界：
未覆盖范围及后续 Issue：
```

## 证据约束

- 只用隔离 development/e2e 合成资料；遵守 `ports/mygo/AGENTS.md`。真实用户资料、生产路径、凭据、密钥、私密日志不得进入公开 Issue、仓库或附件。
- 记录真实命令、环境、exit、日志或产物 hash 与来源版本。未运行就是未运行；源码存在、单测、交叉编译、headless 和原生桌面分别统计。
- 日志和二进制放在显式外置 build root，不把 cache、`.build`、`dist` 或 artifacts 放回源码。
- Actions 证据当前只保留 7 天。保留可审查的脱敏摘要、关键结果与 hash；到期后不要只依赖临时产物链接证明通过。
- 本机制不改变产品功能、测试阈值、CI 权限、release approval、正式 tag/Release、账户或数据访问授权。
