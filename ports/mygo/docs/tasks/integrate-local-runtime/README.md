# 集成本地原生运行链路

task-id: integrate-local-runtime

## 需求与现状

用户要 Go + MyGo 的 Noonmark 完整跨平台复刻。当前上游基线为 43e6eefaae3a04be89cab3e234d470111afd80ef，原型覆盖 20 个画面但无持久化；三批独立模块提供有限任务内核、分类/重复计划和候选 v7 编解码。原 Swift 功能仍是事实来源，不能提前切换。

本轮首先将原型与模块纳入保留上游全部文件和历史的新本地副本 ports/mygo。本地集成在 port/go-mygo 分支，不修改原仓库。用户随后创建并批准 ferrumlux/noonmark-go，首批先备份现有源码，尚未实现下述真实 UI 存储链路。

## 设计与优先级

P 级数据改动。应用服务持有一致性快照，命令在候选副本执行并完整验证，存储成功后才向 UI 发布。第一条真实链路为任务池新增、排到今天/明天、今日完成/撤销、导航计数、关闭重开回读。新任务需要通过 TaskChain/Definition/Trace 接口，不能退回简单 Task JSON。

保留原型视觉回归入口，不把尚未连接的页面计数或样例混入真实数据。真实模式未接入能力显示明确状态，不产生假成功。只允许显式创建的新隔离 session；运行数据不进入默认用户目录，也不访问现有 Noonmark 数据。持久化格式是 Go development 私有封装，不是经过 Swift 验证的数据包导入器。非空分类仍需要完整 audit，当前不得启用。

UI 像素约束沿用 DESIGN.md：1200×768，220px 亮灰侧栏、白色主面、280px 详情；复用现有字号/色板/图标。真实任务列表保持 20px 水平边距、清晰行距、原生可滚动列表；新增按钮和错误只承载真实操作。任务标题不能成为唯一交互身份，控件 key 使用稳定 UUID。

## 风险、回滚与灰度

- 写入失败不得先变更 UI；候选数据应完整验证，读回对账后才发布。
- 并发、损坏、超大输入、symlink、重复提交必须 fail-closed；不自行 repair 用户数据。
- 原型和三批原件保留，可删除新隔离测试 session 后重建，不迁移/覆盖旧 runtime 数据。
- 默认不接管 production；该本地开发入口即灰度边界。监控仅保留无正文的 typed verdict 与测试结果，不记录隐私 payload。

## 验证策略

先跑原型和三批模块回归，再跑真实 UI Tester 操作→应用服务→磁盘→重开→UI 的集成链路，包括取消、重复点击、导航后重开、错误保持草稿、未来任务不能完成、存储失败不发布。外置 build root 进行 Linux 运行与六目标编译。若无显示服务器则真实窗口与系统输入法不可冒称通过；离屏 UI 测试和截图只作为其本身证据。无 Swift oracle 不声称互通，未完成一年故事/SQLite/加密 AI sidecar 的入口不得标成正式演示基线。
