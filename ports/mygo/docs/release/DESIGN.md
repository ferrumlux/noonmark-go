# 六目标发行流水线设计

## 需求与现状

为独立 Go 仓库准备可重现的 Linux、Windows、macOS × amd64、arm64 发行物，保留 AGPL-3.0-only 来源与 MyGo 补丁许可。现有入口只验证 development；六目标编译不代表六目标原生运行验收。本批只准备流水线，不创建 tag、GitHub Release 或改变运行身份。

## 方案与边界

- 只新增发行入口、独立 workflow 与文档，不修改应用或现有 development CI。所有构建、缓存、源代码归档和产物放在显式外置 build root。
- 从干净、已提交的源码与经校验的外置 MyGo workspace 构建。固定 Go 1.27.3，禁用 CGO、VCS 自动注入与本机路径，记录完整 commit、源码摘要、工具链、依赖与补丁摘要。
- 六份便携程序归档、完整对应源代码归档、逐文件 licence/NOTICE、SHA256SUMS 和 JSON manifest 一并生成。平台签名、安装器、桌面启动和实机验收不由交叉编译冒充。
- 发布候选使用 `v0.0.0-dev.<commit>`，在手动运行或 main 的发布流程文件更新时产生只读候选产物。正式 `vMAJOR.MINOR.PATCH` tag 必须通过默认阻断的、与构建源码摘要绑定的完成批准清单，以及该精确 commit 的成功 development CI。
- 发布 workflow 的只读验证阶段完成全部门禁、双次重建比较后，唯一写权限 job 才可创建并发布 Release。任何失败不得覆盖既有 Release；无手工绕过开关。

## 风险与回滚

发行批准文件是维护者对已完成真实验收的声明，不是自动证明业务完整性。缺证、错误摘要、缺平台、错误版本一律阻断。默认清单未批准，因此合并此批不会授权正式发布。归档不包含用户数据、缓存、凭证或工具链。没有签名证书，产物明确标注无发布者签名，不能宣称 Gatekeeper、SmartScreen 或非 Linux 运行已通过。

回滚只需撤回新增流水线与发行入口；应用和原有 CI 不受影响。未有任何发布资产需要撤回。

## 验证计划

单测覆盖 tag、源码绑定、批准清单、缺失证据、路径安全、归档稳定性、篡改校验与 workflow 权限。以当前干净基线运行六目标真实构建，双次输出逐字节比较，解压源码后在禁网模块模式重建并比较原二进制。现有 CI 不由本批改写或宣称替代。
