# 从对应源代码离线重建

安装 `SOURCE.json` 指定的官方 Go 1.27.3 和 Python 3。工具链不随源码包分发。解压此包后，`repository/` 是精确提交的项目源码，`dependencies/` 是本次实际选用的完整依赖模块源码（MyGo 已应用清单中的补丁），`go.work` 使用固定相对路径。原始补丁与校验清单仍在项目源码中保留。

在此包顶层运行，输出目录须尚不存在，并位于解压源码以外：

```sh
python3 -B build.py --go /absolute/path/to/go --output /absolute/external/noonmark-rebuild
```

默认重建全部六目标；可用 `--target linux/amd64` 等选择单一目标。脚本禁用模块代理和校验服务器，使用空的外置模块／构建缓存。网络不是构建的前置条件。构建驱动另需 Python 3；Go 工具链及其自带标准库不捆绑，应用的全部模块依赖源码已包含。

二进制摘要应与同一发行 `manifest.json` 的 `binaries` 字段一致。此重建只编译，不启动程序或检查原生桌面兼容性。Linux 实机启动还需要系统库及中文字型，这些不属于字节级构建可重现性声明。

归档固定文件顺序、权限、uid/gid 与时间戳；Go 关闭构建 ID、源码绝对路径和自动 VCS 注入。发行 CI 必须在两个独立外置根目录构建并比较全部归档字节，并从已生成的对应源码包在禁网模块模式重建六个二进制。未通过则不发布。

归档逐字节比较目前覆盖同一验证环境、不同绝对目录；未证明不同 Python/zlib 版本的压缩输出完全相同。离线六目标二进制重建比较单独执行，不与跨压缩库归档对等混淆。
